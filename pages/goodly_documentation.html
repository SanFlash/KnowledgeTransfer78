Section 01

Product Overview & Core Value Proposition

1.1 Elevator Pitch

Goodly (by Scribble Labs) is an ambient clinical intelligence platform that listens to clinical encounters in real time, extracts structured medical information from natural conversation, and automatically generates regulatory-compliant documentation — eliminating manual charting for home-health and outpatient clinicians.

Core Promise: A clinician speaks naturally during a patient visit. Goodly listens, understands, structures, validates, and delivers a complete OASIS/SOAP note — ready for EHR submission — with zero manual data entry.

1.2 Strategic Differentiation

🎙️ Ambient Capture (Not Push-to-Talk)

Continuous passive recording means clinicians never need to pause, tap, or dictate. The system works in the background while the clinician focuses on the patient.

🧠 Clinical-Grade NLP

Entity extraction tuned for medical vocabulary: medications, NDC codes, NCPDP routing numbers, vital signs, OASIS M-codes, ICD-10 diagnoses.

⚙️ Configurable Structuring

Outputs are mapped to OASIS, SOAP, or custom templates per agency configuration — not a one-size-fits-all transcript dump.

🔄 Bidirectional EHR Integration

FHIR-compatible payload generation with real-time validation against EHR field constraints before submission — reducing rejection rates.

2.3 Offline / Online Sync Mechanics

Offline Mode (Mobile)

  • All capture happens on-device into local SQLite queue
  • Audio blobs stored in encrypted local FS
  • ASR can run on-device (compressed model) or queue for cloud
  • SyncQueue table stores pending operations with retry counters
  • UI shows "Offline · N visits pending sync" banner

Sync Strategy

  • Optimistic local writes; conflict resolution on sync
  • Last-write-wins for non-PHI metadata fields
  • Clinician manual resolution for clinical field conflicts
  • Exponential backoff: 5s → 30s → 2m → 10m → 1h
  • Max retries: 7; after that, manual re-trigger required
  • All sync events logged in AuditEvent table
Conflict Resolution Rule: If two edits to the same structured field arrive from different devices within the same sync window, the system presents a diff to the clinician for manual resolution. Auto-merge is never applied to PHI clinical fields.

Cross-Platform User Flows

3.1 Major Flows

Flow 1 — Scheduling a Visit (Web + Mobile Sync)

1
[Web · Admin] Admin opens Visit Management → clicks "New Visit". Selects patient from patient lookup (search by name/MRN). Picks clinician from active roster. Sets visit type (SOC, ROC, Follow-up, Discharge). Assigns scheduled date/time window. Saves draft.
↓
2
[Server] Visit record created in DB with status SCHEDULED. Push notification enqueued for assigned clinician. Visit appears in clinician's queue immediately if online, or on next sync if offline.
↓
3
[Mobile · Clinician] Clinician opens app → Today's Visits list refreshes. New visit appears with patient name, visit type, and scheduled window. Clinician can tap to pre-load patient context (demographics, prior visit summary, active medications).
↓
4
[Mobile] If offline when scheduled: visit data cached locally on next successful sync. Banner shows "X new visits synced" on reconnection.

Flow 2 — Executing a Live Visit (Mobile)

1
Clinician taps visit → "Start Visit". App requests microphone permission if not granted. Records GPS-stamped visit start event. Visit status → IN_PROGRESS.
↓
2
Recording begins. Audio stream chunked every 5 seconds. Preprocessing applied per chunk. ASR processes in near-real-time (partial results appear). Live transcript scrolls on screen.
↓
3
Real-time entity tagging. Detected medications highlighted in teal, vitals in amber, symptoms underlined. Clinician can tap highlighted items to confirm or correct. Manual structured entries also available via form overlay.
↓
4
Interruption handling. Incoming call → app pauses recording, stores buffer. On return: prompt "Resume recording?" or "Visit was interrupted – continue from last position". Interruption timestamps logged.
↓
5
Clinician taps "End Visit". GPS-stamped end event recorded. Final ASR pass over full audio. Draft generated and displayed. Visit status → DRAFT.

Flow 3 — Reviewing & Editing Documentation

📱 Mobile Quick-Edit

  • Structured field list (scrollable)
  • Tap field → inline text/picker edit
  • Red border on validation errors
  • Swipe-right on field → accept AI suggestion
  • "Review complete" button enabled only after required fields satisfied
  • Auto-save every 30 seconds

🌐 Web Advanced Editor

  • Left panel: Raw transcript with speaker labels
  • Right panel: Structured clinical form
  • Hover transcript segment → highlights corresponding field
  • Inline editing with validation on blur
  • Version compare: current vs previous save
  • Comment threads on individual fields
  • Supervisor override capability with reason code

Flow 4 — Finalizing and Syncing to EHR / Billing

1
Clinician clicks "Submit for Review" (mobile) or "Finalize" (web). Final validation pass runs. Any blocking errors shown (required fields, invalid NDC). Non-blocking warnings listed but do not prevent submission.
↓
2
Supervisor review (if workflow configured). Supervisor notified via push/email. Reviews in web editor. Approves or sends back with comments. Status → APPROVED or REVISION_REQUIRED.
↓
3
EHR sync initiated. FHIR resource bundle constructed. POST to configured EHR endpoint. Response parsed: success → status SYNCED. Rejection → error code stored, notification sent, status SYNC_FAILED.
↓
4
Billing payload generated (if billing integration enabled). CMS-1500 / UB-04 fields populated from visit record. Submitted to billing endpoint. ERA response reconciled and linked to visit record.

Flow 5 — Admin Batch Audit & Correction (Web)

Admins and supervisors managing high-volume operations require bulk tooling on the web platform.

1
Admin opens Data Quality Console. Applies filters: date range, clinician, error type (e.g., "Invalid NDC"), status. Grid shows matching visits with error summaries.
↓
2
Selects multiple visits → "Batch Correct" or opens individual visit for inline fix. For known systematic errors (e.g., all NCPDP codes zero), uses bulk find-replace tool with confirmation dialog.
↓
3
Each correction auto-logs: who changed, what changed, from/to values, timestamp. Corrections trigger re-validation. On pass: status updated; on fail: new error type recorded.

3.2 Minor Flows

Flow 6 — User Role Management & Permission Changes

Performed by Admin in the web User Management module. Admin selects user → "Edit Role" → selects new role from dropdown (Clinician, Supervisor, Admin, Auditor, Billing Analyst) → confirms. Role change takes effect on next user session. Downgrade from Admin requires second admin confirmation. All role changes logged in AuditEvent.

Flow 7 — Mapping Configuration (NDC, NCPDP, Custom Fields)

Admin navigates to Integration Settings → Mapping Tables. Can import CSV mapping files (drug name → NDC, pharmacy chain → NCPDP). System validates format on upload — shows row-level errors. Published mappings apply to all new visit validations immediately. Existing visits must be re-validated via "Re-validate Affected Visits" action.

Flow 8 — Exporting Reports / Analytics

From the Dashboard or Visit Management grid: click "Export" → choose format (CSV, XLSX, PDF). Select date range and columns. Large exports (>10k rows) queued as background jobs; user notified via email with download link. All export events logged (who, what, when, IP address) for HIPAA audit purposes.

Flow 9 — Handling Sync Conflicts (Manual Resolution)

When a conflict is detected (concurrent edits from mobile + web): system places visit in CONFLICT state. Notifies both users. Web shows side-by-side diff (version A from mobile, version B from web). Clinician selects winning value per field or manually types merged value. Resolution event logged. Visit re-validated and status returns to DRAFT.

Flow 10 — Multi-Visit Day Batch Review

At end of shift, clinician opens "Day Summary" view on mobile: all visits listed with completion percentage and error count. Bulk-accept AI suggestions for low-confidence fields. Submit all approved visits in a single tap. Visits with unresolved errors highlighted — cannot bulk-submit until resolved.

Flow 11 — Manual Data Override & Re-Validation

Supervisor or Admin can apply a "Manual Override" to any field on a finalized visit. Override requires: new value, reason code (from standardized list), and free-text justification. Override creates new FieldVersion record. Visit re-validated against rules with override values. Overrides are immutable — cannot be deleted, only superseded by a newer override.

Flow 12 — Audit Log Exploration

Compliance Auditor opens Audit & Compliance Logs. Filters by: event type (login, edit, export, override, sync), user, patient ID, date range. Each entry shows: timestamp, actor, action, target entity ID, IP address, change summary (field before/after). Logs are read-only — no edit or delete capability. Export to CSV or PDF available, itself logged as an export event.

Section 07

AI Processing & Clinical NLP Pipeline

7.1 ASR — Speech-to-Text Engine

Acoustic Model

  • Base: large transformer (Whisper-class or equivalent)
  • Fine-tuned on clinical encounter data (home health + outpatient)
  • Accent adaptation: training corpus includes diverse US regional accents
  • Noise robustness: trained with augmented home environment noise profiles

Language Model

  • Medical vocabulary bias: RxNorm drug names, SNOMED CT terms, ICD-10
  • N-gram boost for medication names at prediction time
  • Temporal phrase recognition (e.g., "three times daily", "two weeks ago")
  • Disfluency handling: "uh", "um" filtered; false starts handled

7.2 Clinical NLP Entity Extraction

The NLP pipeline uses a multi-label Named Entity Recognition (NER) model with relation extraction:

7.3 Structuring Engine — Template Mapping

Extracted entities are mapped to structured form fields using a configurable mapping registry. Three built-in templates are provided:

OASIS-E Template

  • M0010–M2401 data items
  • SOC/ROC/FU/D/C variants
  • Clinical section grouping
  • CMS skip logic enforced

SOAP Note Template

  • Subjective: CC, HPI, ROS
  • Objective: vitals, exam findings
  • Assessment: diagnoses (ICD-10)
  • Plan: medications, follow-up

Custom Template

  • Agency-defined fields
  • JSON Schema definition
  • Mapped to EHR extension fields
  • Validation rules configurable

8.2 Business Rules (Visit Level)

Visit Completeness Threshold: A visit must have all required OASIS M-items populated for its visit type (SOC vs. ROC vs. D/C) before it can be submitted. Missing items are enumerated with OASIS item numbers in the validation report. 
// Example: Cross-field medication rule
RULE medication_acute_supply_check:
  WHEN medication.frequency IN ["QD", "BID", "TID"]
    AND medication.days_supply > 30
    AND visit.visit_type = "SOC"
  THEN WARNING("Acute visit with >30 day supply. Verify if chronic medication.")

// NDC/NCPDP cross-validation
RULE ncpdp_not_zero:
  WHEN medication.ncpdp_code = "0000000"
  THEN ERROR("NCPDP code is all zeros — likely missing mapping configuration.")

// Wound stage progression
RULE wound_stage_regression:
  WHEN current_visit.wound.stage > previous_visit.wound.stage
    AND (current_visit.date - previous_visit.date) < 7 // days
  THEN WARNING("Wound stage worsened within 7 days. Clinical documentation required.")

Section 11

Security & Compliance

11.1 HIPAA Controls

Technical Safeguards

  • Encryption at rest: AES-256 (database fields, S3 objects, local SQLite via SQLCipher)
  • Encryption in transit: TLS 1.2+ for all API calls; certificate pinning on mobile
  • PHI field-level encryption in database (separate KMS key per agency)
  • Automatic session timeout (30min inactivity on web; configurable)
  • MFA required for admin and auditor roles; optional for others
  • API keys hashed (SHA-256) before storage; never logged in plaintext

Organizational Safeguards

  • BAA (Business Associate Agreement) required for all agency customers
  • Data residency: PHI stored in US-East AWS regions only (configurable)
  • Breach notification workflow: automated alerting within 1 hour of anomaly detection
  • Annual penetration testing + SOC 2 Type II audit
  • Employee PHI access: role-based; audit logged; quarterly access review

11.3 Vulnerability & Incident Response

  • SAST (static analysis) integrated in CI/CD pipeline — blocks merge on critical findings
  • Dependency scanning (Snyk/Dependabot) with automatic PRs for security patches

Section 13

Glossary & Acronyms

ASR
Automatic Speech Recognition — converts spoken audio to text. In Goodly, tuned for medical vocabulary and home-health encounter audio.
BAA
Business Associate Agreement — HIPAA-required contract between a covered entity (agency) and a service provider (Scribble Labs) handling PHI.
D/C
Discharge visit — the final home health visit type; requires specific OASIS items documenting patient status at discharge.
EHR
Electronic Health Record — the clinical system of record for patient data. Goodly integrates via FHIR/HL7 APIs.
ERA
Electronic Remittance Advice — payer response to a billing claim indicating payment, denial, or adjustment.
FHIR
Fast Healthcare Interoperability Resources (HL7 standard, R4) — the API format used for EHR data exchange in Goodly integrations.
HL7
Health Level 7 — the standards organization behind FHIR, V2, and V3 healthcare messaging formats.
ICD-10
International Classification of Diseases, 10th Revision — standardized diagnosis codes used in clinical documentation and billing.
NDC
National Drug Code — FDA-assigned 10 or 11-digit identifier for specific drug products. Required for billing and medication documentation.
NCPDP
National Council for Prescription Drug Programs — standards body; their 7-digit routing codes identify pharmacies in claims processing.
NER
Named Entity Recognition — NLP task of identifying and classifying named entities (medications, vitals, etc.) in text.
NLP
Natural Language Processing — AI/ML techniques for understanding and extracting meaning from human language. Core of Goodly's AI processing layer.
NPI
National Provider Identifier — 10-digit number assigned to healthcare providers in the US. Required on billing claims.
OASIS
Outcome and Assessment Information Set — CMS-mandated standardized assessment tool for home health agencies. Defines M-item data elements.
PHI
Protected Health Information — any individually identifiable health information subject to HIPAA privacy and security rules.
ROC
Resumption of Care — OASIS visit type performed when a patient returns to home health service after a hospitalization.
RxNorm
NLM standardized drug nomenclature system used to normalize medication names across drug databases.
SNOMED CT
Systematized Nomenclature of Medicine Clinical Terms — comprehensive clinical terminology used for symptoms, conditions, and procedures.
SOAP
Subjective, Objective, Assessment, Plan — standard clinical note format used in outpatient and ambulatory care settings.
SOC
Start of Care — the initial OASIS visit when a patient begins a home health episode. Most comprehensive visit type.
VAD
Voice Activity Detection — algorithm that distinguishes speech from silence or noise, used to gate ASR processing.
WAL
Write-Ahead Log — SQLite journaling mode ensuring data integrity and crash recovery for local mobile database.
WER
Word Error Rate — primary ASR accuracy metric: (substitutions + deletions + insertions) / total reference words.
