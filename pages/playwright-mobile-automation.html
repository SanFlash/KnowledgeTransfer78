⚠️ Critical — Enable Virtualization

Before installing Android Studio, enable Intel VT-x or AMD-V in your BIOS/UEFI. Without this, Android emulators run at 1/10th speed and are unusable. Reboot → press F2/Del/F12 → Advanced CPU settings → Enable Virtualization Technology.

Node.js + NPM Installation

The JavaScript runtime that powers everything — understanding versions, NVM, and package management

1

Install NVM for Windows (Node Version Manager)

Never install Node.js directly. Use NVM so you can switch Node versions across projects. Different projects may need different Node versions. This is the industry standard approach.

2

Download NVM-Windows

Go to github.com/coreybutler/nvm-windows/releases and download nvm-setup.exe. Run as Administrator. Accept defaults. This installs NVM at C:\Users\[name]\AppData\Roaming\nvm.

3

Install Node.js LTS via NVM

Playwright officially supports Node.js 18 LTS and 20 LTS. We use 20 LTS for maximum compatibility with all Playwright features including new mobile APIs.

4

Verify Installation

Confirm Node and NPM are in PATH and working. A clean install shows version numbers without any errors.

PowerShell (Admin) — Node.js Setup

💡 Why NVM? — Industry Best Practice

In a real team, different projects may pin different Node versions. NVM lets you switch with one command: nvm use 18 or nvm use 20. This avoids the "works on my machine" problem caused by Node version mismatches. CI pipelines also use specific Node versions — matching locally prevents surprises.

Understanding NPM
📦

package.json

Your project's manifest. Lists all dependencies, scripts, metadata. Created by npm init. Every automation project starts here.

🔒

package-lock.json

Locks exact dependency versions. Ensures identical installs across team members and CI. Always commit this file to Git.

📁

node_modules/

Where packages are installed. NEVER commit to Git (add to .gitignore). Regenerated from package-lock.json via npm ci.

🛠️

npm scripts

Custom commands in package.json. npm test, npm run regression, npm run smoke. Industry standard for running tests.

🎯 Interview Questions — Git in Automation
Q: Why should .env files never be committed to Git?
A: .env files contain secrets like API keys, passwords, and credentials. If committed to a public repo, they're exposed to the internet permanently (even if deleted later — Git history retains them). Use GitHub Secrets or environment variables in CI instead.
Q: What branching strategy do you use for automation frameworks?
A: Feature branching — main (stable), develop (integration), feature/login-tests (new tests). PRs require code review before merging. CI runs the full suite on every PR to catch regressions before they reach main.

Download Android Studio

2

SDK Manager — Install Required SDK Versions

Open Android Studio → SDK Manager → Install Android 13 (API 33) and Android 14 (API 34). These match current production devices. Always have the two latest stable versions.

ADB — Android Debug Bridge Mastery

The command-line tool that communicates with Android devices — essential for automation debugging

🔌 What is ADB?

ADB (Android Debug Bridge) is a versatile command-line tool that allows communication between your development machine and an Android device. It's your direct line to install APKs, capture logs, take screenshots, simulate input, and inspect the device — all from a terminal. Even when using Appetize for cloud testing, understanding ADB is essential for local debugging and APK validation.

ADB Essential Commands for Automation Engineers
## DEVICE MANAGEMENT
$ adb devices # List connected devices
$ adb devices -l # List with details
$ adb connect 192.168.1.100:5555 # Connect to network device
$ adb kill-server # Restart ADB server
$ adb start-server
 
## APK MANAGEMENT
$ adb install path/to/app.apk # Install APK
$ adb install -r path/to/app.apk # Reinstall (keep data)
$ adb uninstall com.tabletennis.app # Uninstall by package
 
## APP CONTROL
$ adb shell monkey -p com.tabletennis.app -c android.intent.category.LAUNCHER 1
$ adb shell am force-stop com.tabletennis.app
$ adb shell pm clear com.tabletennis.app # Clear app data
 
## LOGGING (essential for debugging test failures)
$ adb logcat # All device logs
$ adb logcat -s "TableTennis" # Filter by tag
$ adb logcat *:E # Only errors
$ adb logcat -d > device.log # Save to file
 
## SCREENSHOTS & SCREEN RECORDING
$ adb exec-out screencap -p > screen.png
$ adb shell screenrecord /sdcard/test.mp4
$ adb pull /sdcard/test.mp4 ./recordings/
 
## INPUT SIMULATION
$ adb shell input tap 540 1200 # Tap at x,y
$ adb shell input swipe 300 800 300 400 500 # Swipe up
$ adb shell input text "hello123" # Type text
$ adb shell input keyevent 66 # Enter key
$ adb shell input keyevent 4 # Back button
 
## MULTIPLE DEVICES — specify -s flag
$ adb -s emulator-5554 install app.apk
$ adb -s emulator-5556 logcat
🚫 Common ADB Mistakes

1. "device unauthorized" — Enable Developer Options on device → Enable USB Debugging → Accept the RSA fingerprint popup.

2. "adb: command not found" — ANDROID_HOME path not set or terminal not restarted after setting env vars.

3. Multiple devices connected, no -s flag — ADB throws "error: more than one device/emulator". Always use -s with the device serial when running parallel tests.

Appetize.io Cloud Setup

Setting up cloud-based Android and iOS devices — APK upload, session management, and automation connection

☁️ What is Appetize.io?

Appetize.io is a cloud platform that streams real Android and iOS device simulators in your browser. Instead of maintaining physical devices or local emulators, your tests interact with a device rendered as a web page. Playwright controls this page via its standard browser automation API — meaning the same Playwright skills you use for web automation work for mobile too.

1️⃣

Create Account

Sign up at appetize.io. Free tier gives 100 minutes/month — enough for learning. Team plans for production CI pipelines.

2️⃣

Get API Token

Dashboard → Account Settings → API Token. Copy this. Never commit to Git. Store in .env as APPETIZE_API_TOKEN.

3️⃣

Upload APK/IPA

Dashboard → New App → Upload APK (Android) or IPA (iOS). Get the Public Key (app identifier) after upload. Store as APPETIZE_APP_KEY.

4️⃣

Generate Session URL

Session URL format: https://appetize.io/embed/[appKey]?device=pixel7&osVersion=13&autoplay=true. This URL is what Playwright navigates to.

Upload APK via Appetize REST API
# Upload APK using curl (or use the dashboard)
$ curl --http1.1 https://api.appetize.io/v1/apps \
-H "Authorization: Token YOUR_API_TOKEN" \
-F "file=@./apps/tabletennis.apk" \
-F "platform=android"
 
# Response — save the publicKey!
{
"publicKey": "abc123xyz456...",
"platform": "android",
"bundle": "com.tabletennis.app"
}
 
# Save to .env
APPETIZE_API_TOKEN=your_token_here
APPETIZE_ANDROID_KEY=abc123xyz456
APPETIZE_IOS_KEY=def789uvw012
utils/appetize-session.js — Session Manager 
/**
 * Appetize Session Manager
 * Manages cloud device session lifecycle for mobile automation
 */
const { chromium } = require('@playwright/test');
require('dotenv').config();

class AppetizeSession {
  constructor(options = {}) {
    this.apiToken = process.env.APPETIZE_API_TOKEN;
    this.platform = options.platform || 'android';
    this.appKey = options.appKey ||
      (this.platform === 'android'
        ? process.env.APPETIZE_ANDROID_KEY
        : process.env.APPETIZE_IOS_KEY);
    this.device = options.device || 'pixel7';
    this.osVersion = options.osVersion || '13';
    this.browser = null;
    this.page = null;
  }

  /**
   * Build the Appetize embed URL with all parameters
   */
  buildSessionURL() {
    const params = new URLSearchParams({
      device: this.device,
      osVersion: this.osVersion,
      autoplay: 'true',
      orientation: 'portrait',
      centered: 'true',
      deviceColor: 'black',
      scale: 'auto',
    });

    return `https://appetize.io/embed/${this.appKey}?${params.toString()}`;
  }

  /**
   * Start a new cloud device session
   */
  async start() {
    this.browser = await chromium.launch({ headless: !!process.env.CI });

    const context = await this.browser.newContext({
      viewport: { width: 1280, height: 900 },
    });

    this.page = await context.newPage();

    // Navigate to Appetize embed page
    const sessionURL = this.buildSessionURL();
    await this.page.goto(sessionURL, { waitUntil: 'networkidle' });

    // Wait for device to boot and app to launch
    await this.waitForDeviceBoot();

    console.log(`✅ Appetize session started: ${this.platform} / ${this.device}`);
    return this.page;
  }

  /**
   * Wait for the device screen to be interactive
   */
  async waitForDeviceBoot(timeout = 60000) {
    // Appetize renders device in an iframe
    await this.page.waitForSelector(
      'iframe[data-testid="appetize-device-frame"]',
      { timeout }
    );

    // Wait additional time for app to fully launch
    await this.page.waitForTimeout(5000);
  }

  /**
   * Gracefully end the session
   */
  async end() {
    if (this.browser) {
      await this.browser.close();
      console.log('✅ Appetize session ended');
    }
  }

  /**
   * Get the device frame for interaction
   */
  async getDeviceFrame() {
    const frameElement = await this.page.$(
      'iframe[data-testid="appetize-device-frame"]'
    );
    return frameElement.contentFrame();
  }
}

module.exports = { AppetizeSession };

js-essentials-for-qa.js — Core Concepts 
// ═══════════════════════════════════════════════
// 1. ASYNC / AWAIT — The heartbeat of automation
// ═══════════════════════════════════════════════

// Every Playwright action is async (it takes time)
// Without async/await, actions execute before they complete

// ❌ WRONG — No await, assertion runs before page loads
function badTest() {
  page.goto('https://sttc.onrender.com'); // Not awaited!
  expect(page).toHaveTitle('TableTennis'); // Runs immediately — FAIL
}

// ✅ CORRECT — await ensures sequential execution
async function goodTest() {
  await page.goto('https://sttc.onrender.com'); // Wait for navigation
  await expect(page).toHaveTitle('TableTennis'); // Then assert
}

// ═══════════════════════════════════════════════
// 2. DESTRUCTURING — Clean code in fixtures
// ═══════════════════════════════════════════════
const { page, browser, context } = fixtures; // Object destructuring
const [firstResult, ...rest] = testResults; // Array destructuring

Playwright Architecture Deep Dive

Understanding how Playwright works internally — the foundation for writing reliable tests

🌐

Browser

The top-level object. Represents a Chromium/Firefox/WebKit instance. Multiple browsers can run in parallel. Each test typically gets its own browser.

📂

BrowserContext

Isolated browser session. Own cookies, localStorage, auth state. Tests run in separate contexts — no data leakage between tests. This is key for test isolation.

📄

Page

A single tab/window. The object you interact with most. Navigate, click, fill, assert — all on the Page. One context can have multiple pages.

🔍

Locator

Represents an element — deferred and auto-waited. Never throws immediately. Built-in retry logic. Preferred over $ and $$ selectors.

  const browser = await chromium.launch();

Phase 3 — Mobile Automation with Appetize

Cloud-based Android and iOS test automation — architecture, gestures, and session management

🏗️ How Appetize + Playwright Works Together

Appetize streams a real Android/iOS device as a web page in your browser. The device screen is rendered inside an <iframe>. Playwright navigates to this page, finds the iframe, and then interacts with the device through mouse events that Appetize translates to touch events. This is the key architectural insight: you're automating the web UI that controls the device, not the device directly.

3.1

Appetize Architecture & Session Lifecycle

The complete flow from test start to device interaction

Step 01
Test Starts → Playwright Launches Browser
A real Chromium/Firefox browser opens (or headless in CI). This is your "control browser" — it's what you use to interact with Appetize's web interface.
Step 02
Navigate to Appetize Embed URL
Playwright navigates to appetize.io/embed/[appKey]?device=pixel7. This loads the Appetize player UI in the browser.
Step 03
Appetize Allocates Cloud Device
Appetize's infrastructure spins up a real Android/iOS virtual device in their cloud. The device boots your uploaded APK/IPA automatically.
Step 04
Device Screen Streams to Browser
The device display is video-streamed into the <iframe> element on the page. You see the actual mobile screen in real time.
Step 05
Playwright Interacts via Mouse Events
Playwright clicks, types, and scrolls inside the iframe. Appetize translates these mouse events to touch events on the virtual device. Your page.click() becomes a mobile tap.
Step 06
Session Ends → Device Released
After the test, browser.close() ends the session. The cloud device is released back to the pool. Logs and video are available via API.

/**
 * MobileGestures — Reusable gesture library for Appetize automation
 * All coordinates are relative to the device iframe
 */
class MobileGestures {
  constructor(frame) {
    this.frame = frame; // Appetize device iframe
  }

  /**
   * TAP — Standard single touch at position
   * @param {number} x - Horizontal position (0-100% of screen width)
   * @param {number} y - Vertical position (0-100% of screen height)
   */
  async tap(x, y) {
    await this.frame.mouse.click(x, y);
    await this.frame.waitForTimeout(300); // Small delay for animation
  }

  /**
   * LONG PRESS — Triggers context menus, drag handles
   * @param {number} x - X coordinate
   * @param {number} y - Y coordinate
   * @param {number} duration - Press duration in ms (default 800ms)
   */
  async longPress(x, y, duration = 800) {
    await this.frame.mouse.move(x, y);
    await this.frame.mouse.down();
    await this.frame.waitForTimeout(duration);
    await this.frame.mouse.up();
  }

  /**
   * SWIPE UP — Scroll down the page (natural scroll direction)
   * @param {number} startY - Starting Y position
   * @param {number} distance - Pixels to swipe
   */
  async swipeUp(startY = 600, distance = 300) {
    const centerX = 180; // Center of device screen
    await this.frame.mouse.move(centerX, startY);
    await this.frame.mouse.down();
    // Gradual movement simulates real finger swipe
    await this.frame.mouse.move(centerX, startY - distance, { steps: 20 });
    await this.frame.mouse.up();
    await this.frame.waitForTimeout(500);
  }

  /**
   * SWIPE DOWN — Pull to refresh gesture
   */
  async swipeDown(startY = 200, distance = 300) {
    const centerX = 180;
    await this.frame.mouse.move(centerX, startY);
    await this.frame.mouse.down();
    await this.frame.mouse.move(centerX, startY + distance, { steps: 20 });
    await this.frame.mouse.up();
    await this.frame.waitForTimeout(800); // Wait for refresh animation
  }

  /**
   * SCROLL TO ELEMENT — Find element even if off screen
   * Keeps swiping up until element is visible
   */
  async scrollToElement(selector, maxSwipes = 10) {
    for (let i = 0; i < maxSwipes; i++) {
      try {
        const element = await this.frame.waitForSelector(selector, { timeout: 2000 });
        const isVisible = await element.isVisible();
        if (isVisible) return element;
      } catch (e) { /* not found yet */ }
      await this.swipeUp();
    }
    throw new Error(`Element ${selector} not found after ${maxSwipes} swipes`);
  }

  /**
   * DRAG AND DROP — Move items in lists
   */
  async dragAndDrop(fromX, fromY, toX, toY) {
    await this.frame.mouse.move(fromX, fromY);
    await this.frame.mouse.down();
    await this.frame.waitForTimeout(500); // Trigger drag state
    await this.frame.mouse.move(toX, toY, { steps: 30 });
    await this.frame.mouse.up();
    await this.frame.waitForTimeout(500);
  }

  /**
   * TYPE TEXT — Enter text in focused field
   */
  async typeText(text) {
    await this.frame.keyboard.type(text, { delay: 50 }); // Human-like typing
  }

  /**
   * PRESS ANDROID BACK — Hardware back button
   */
  async pressBack() {
    await this.frame.keyboard.press('Escape'); // Maps to Android back
    await this.frame.waitForTimeout(300);
  }
}

  constructor(page) {
    this.page = page;
  }

  // ── Navigation ──────────────────────────────
  async navigate(path = '') {
    const baseURL = process.env.BASE_URL || 'https://sttc.onrender.com';
    await this.page.goto(`${baseURL}${path}`);
    await this.waitForPageLoad();
  }

  // ── Wait Strategies ──────────────────────────
  async waitForPageLoad() {
    await this.page.waitForLoadState('domcontentloaded');
    await this.page.waitForLoadState('networkidle');
  }

  async waitForElement(selector, options = {}) {
    return await this.page.waitForSelector(selector, {
      state: 'visible',
      timeout: 10000,
      ...options
    });
  }

  // ── Screenshot ───────────────────────────────
  async takeScreenshot(name) {
    const timestamp = new Date().toISOString().replace(/[:.]/g, '-');
    await this.page.screenshot({
      path: `screenshots/${name}-${timestamp}.png`,
      fullPage: true
    });
  }

  // ── Form Helpers ─────────────────────────────
  async fillInput(locatorOrSelector, value) {
    const el = typeof locatorOrSelector === 'string'
      ? this.page.locator(locatorOrSelector)
      : locatorOrSelector;

    await el.waitFor({ state: 'visible' });
    await el.clear();
    await el.fill(value);
  }

  // ── URL Verification ─────────────────────────
  async getCurrentURL() {
    return this.page.url();
  }

  async isOnPage(urlPattern) {
    return this.page.url().match(urlPattern) !== null;
  }
}

module.exports = { BasePage };

/**
 * Custom Logger — Structured logging for automation framework
 * Levels: DEBUG | INFO | WARN | ERROR
 * Output: Console + File (logs/test-execution.log)
 */
const fs = require('fs');
const path = require('path');

class Logger {
  constructor(context = 'Test') {
    this.context = context;
    this.logFile = path.join('logs', `test-${new Date().toISOString().split('T')[0]}.log`);
    this.ensureLogDir();
  }

  ensureLogDir() {
    if (!fs.existsSync('logs')) fs.mkdirSync('logs', { recursive: true });
  }

  formatMessage(level, message, data = null) {
    const timestamp = new Date().toISOString();
    const dataStr = data ? ' | ' + JSON.stringify(data) : '';
    return `[${timestamp}] [${level}] [${this.context}] ${message}${dataStr}`;
  }

  write(level, message, data) {
    const formatted = this.formatMessage(level, message, data);
    console.log(formatted);
    fs.appendFileSync(this.logFile, formatted + '\n');
  }

  info(msg, data) { this.write('INFO ', msg, data); }
  debug(msg, data) {
    if (process.env.LOG_LEVEL === 'debug') this.write('DEBUG', msg, data);
  }
  warn(msg, data) { this.write('WARN ', msg, data); }
  error(msg, data) { this.write('ERROR', msg, data); }
  step(stepName) { this.info(`▶ STEP: ${stepName}`); }
  pass(msg) { this.info(`✅ PASS: ${msg}`); }
  fail(msg, err) { this.error(`❌ FAIL: ${msg}`, { error: err?.message }); }
}

module.exports = { Logger };

utils/retry.js — Smart Retry for Flaky Operations 
/**
 * Smart Retry Utility
 * Retries async operations with exponential backoff
 * Essential for cloud device interactions that can be flaky
 */
async function withRetry(operation, options = {}) {
  const {
    maxAttempts = 3,
    delay = 1000,         // Initial delay in ms
    backoff = 2,           // Multiply delay by this each retry
    onRetry = null,        // Called on each retry attempt
    retryOn = null,        // Function to check if error is retryable
  } = options;

  let lastError;
  let currentDelay = delay;

  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await operation();
    } catch (error) {
      lastError = error;

      // Check if this error type should be retried
      if (retryOn && !retryOn(error)) throw error;
      if (attempt === maxAttempts) break;

      if (onRetry) await onRetry(attempt, error);

      console.warn(`Attempt ${attempt}/${maxAttempts} failed: ${error.message}. Retrying in ${currentDelay}ms...`);
      await new Promise(resolve => setTimeout(resolve, currentDelay));
      currentDelay *= backoff; // Exponential backoff
    }
  }

  throw new Error(`Operation failed after ${maxAttempts} attempts: ${lastError.message}`);
}

// Usage example
const result = await withRetry(
  () => session.getDeviceFrame(),
  {
    maxAttempts: 3,
    delay: 2000,
    retryOn: (err) => err.message.includes('timeout'),
    onRetry: (attempt) => console.log(`Retrying session start (attempt ${attempt})`),
  }
);

Production Best Practices Summary
🎯

Selector Hierarchy

data-testid → ARIA role → text → CSS → XPath. Never use CSS classes that might change with styling updates.

⚡

Auth State Caching

Login once, save storageState. Inject auth state in each test's context. Saves 3–5 seconds per test in large suites.

🔄

Explicit Waits Only

Never use waitForTimeout(3000) as a crutch. Use waitForSelector, waitForURL, waitForResponse. Fixed timeouts are the #1 cause of flaky tests.

🧩

Test Isolation

Each test must be independently runnable. No shared state between tests. Use beforeEach + afterEach for setup/teardown. Tests can run in any order.

📊

Tag Every Test

Add @smoke, @regression, @mobile tags. Enables targeted execution: smoke on PR, full regression nightly.

🔍

Trace on Failure

Configure trace: 'retain-on-failure'. Trace files show exact DOM state, network calls, and screenshots at every step — essential for debugging CI failures.

🎯 Senior-Level Interview Questions
Q: How do you prevent test flakiness in a large Playwright suite?
A: (1) Use Playwright's built-in auto-retry in locators, never hardcoded waits. (2) Ensure test isolation — no shared state. (3) Use retries: 2 in CI config. (4) Use network interception to mock unstable APIs. (5) Analyze flaky tests with trace viewer to find root cause. (6) For mobile Appetize tests, add smart retry on session errors.
Q: Explain the Appetize + Playwright integration architecture.
A: Appetize streams a cloud mobile device as a web page with an iframe containing the device screen. Playwright navigates to this URL and interacts with the iframe — mouse events are translated by Appetize into touch events on the virtual device. For mobile selectors, we use resource-id attributes (Android) or accessibility IDs (iOS) visible through the Appetize session. Session lifecycle: start → wait for boot → interact → collect logs → end.
Q: How do you structure a framework for a team of 10 engineers?
A: (1) Clear folder separation: tests/, pages/, utils/, fixtures/. (2) Base classes for all page objects — shared utilities in one place. (3) .env.example documents all required vars. (4) Central selector registry — one change updates all tests. (5) Git workflow: feature branches + PRs + smoke tests as PR gate. (6) Allure reports deployed to GitHub Pages for stakeholder visibility. (7) Naming conventions enforced via ESLint rules.
